# Instagram インサイト分析

Instagram のインサイトを自動でグラフ化・分析する Web アプリです。

- **フォロワーの増減**：総フォロワー数の推移、日次の純増減（フォロー − フォロー解除）
- **アカウントの活動**：リーチ（うちフォロワー以外へのリーチ）とビューの推移、プロフィールアクセス／リンククリック／コンテンツインタラクションの推移、**予約までの導線**（リーチ → プロフィールアクセス → リンククリック・フォロー の通過率）
- **エンゲージメント率**：投稿ごとの ER（投稿タイプ別）、週平均、投稿タイプ別の平均 ER
- **投稿ごとの反応**：上位10投稿（ER・リーチ・ビュー・いいね・保存・フォローなどで切り替え）、全投稿一覧（並べ替え・検索・CSV 出力）
- **フォロワーの内訳**：年齢層 × 性別、上位の国、上位の都市
- **HPへの流入（GA4）**：Instagram から着地先ホームページへの流入（オーガニック／広告の内訳、アカウント別、UTM キャンペーン別）と、**投稿と流入の相関**（相関係数・順位相関・p 値・95% 信頼区間・偏相関・差分相関）、リンククリックの到達率
- **最適な投稿時間帯**：曜日 × 時間帯のヒートマップ、おすすめ投稿枠トップ5、時間帯別・曜日別の平均 ER
- **ストーリーズ**：日ごとの閲覧数・リーチ、投稿した時間帯別の平均閲覧率、見た人のその後（次へ／戻る／離脱／スキップ）、ストーリーズ一覧（CSV 出力）
- **どこで見られているか**：フィード・リール・ストーリーズ・広告の面別の閲覧数とリーチ、プロフィールからのアクション（ウェブサイト・電話・メッセージなど）、リーチのフォロワー／フォロワー以外の内訳とフォロワー転換率
- **ハッシュタグ分析**：タグごとの平均 ER と全体平均との比較／ソーシャルインサイトの集計（書き出し・期間ごとに切り替え）
- **他アカウントとの関係**：フォロー中アカウント（競合・関連先のフォロワー規模とよく使うタグ）、自社をタグ付け・メンションした投稿
- **自動分析レポート**：上記から「好調／要注意／参考」の所見を自動で文章化
- **レポート出力**：画面右上の「レポート出力」から、表示中の期間・絞り込みのすべての数値と分析（主要指標・自動分析・日次データ・面別の内訳・ストーリーズ・全投稿・時間帯・GA4・相関・フォロワー内訳・ハッシュタグ・他アカウントとの関係）を1ファイルにまとめて **Markdown（.md）** または **Word（.docx、A4横）** で保存
- 期間（7日／30日／90日／180日／全期間）の切り替えと前期間比較、アカウントの絞り込み、ライト／ダークモード、各グラフの「表で見る」

## 起動方法

Node.js 18 以上が必要です。

```bash
npm install
npm start
```

ブラウザで http://localhost:5173 を開きます。`http://localhost:5173/?demo` を開くとデモデータで全機能を確認できます。

## サーバーへの公開

```bash
npm install
npm run build
```

`docs/` にアップロード用のファイル一式が、`release/insta-insight-analyzer_日付.zip` に同じ内容の ZIP ができます。
サーバー側のプログラム（PHP・Node.js など）は不要で、HTML/CSS/JS を置ける Web サーバーならどこでも動きます。

- **レンタルサーバー（エックスサーバー・さくら・ロリポップ等）**：`docs/` の**中身**を FTP やファイルマネージャーで公開フォルダ（例: `public_html/insta/`）にアップロードします。`.htaccess` も一緒にアップロードしてください（隠しファイルなので FTP ソフトの設定で表示させる必要がある場合があります）。
- **GitHub Pages**：リポジトリの Settings → Pages で「Deploy from a branch」→ ブランチ `main` → フォルダ `/docs` を選ぶと、`docs/` がそのまま配信されます（ビルド結果は git 管理に含めています）。
- **Netlify / Cloudflare Pages**：`docs/` フォルダをそのまま公開ディレクトリに指定します。
- ルート直下（`https://example.com/`）でもサブフォルダ（`https://example.com/insta/`）でも動きます。
- **HTTPS で公開してください。** アクセストークンを入力する画面があるため、http のままだと通信経路で盗み見られるおそれがあります。SSL 設定済みなら `.htaccess` 末尾の HTTPS 転送のコメントを外すと、http でのアクセスを自動で https へ転送します。
- データは見る人それぞれのブラウザに保存されます。同じ URL を複数人で開いても、互いのデータやトークンは見えません。

## データの取り込み方法

画面右上の「データ接続・更新」から次の4通りで取り込めます。

### 1. Instagram API 連携（おすすめ）

Instagram の**プロアカウント（ビジネスまたはクリエイター）**が必要です。

1. [Meta for Developers](https://developers.facebook.com/) でアプリを作成し、「Instagram」のユースケースを追加します。
2. 「Instagram ログインによる API 設定」でアカウントを追加してアクセストークンを生成します。
   必要な権限は `instagram_business_basic` と `instagram_business_manage_insights` です。
3. アプリの「データ接続」で **ログイン方式 = Instagram ログイン**、ユーザーID は `me` のまま、トークンを貼り付けて「取得して分析」を押します。

Facebook ページ連携（Facebook ログイン、`EAA…` で始まるトークン）の場合は、ログイン方式を **Facebook ログイン** にして「ID を検出」を押すと、Instagram ビジネスアカウント ID が自動入力されます。必要な権限は `instagram_basic`、`instagram_manage_insights`、`pages_show_list`、`pages_read_engagement` です。

**API の制約と対応**

- フォロワーの日次データは API から**直近30日分**しか取得できません。取得するたびに履歴をブラウザに蓄積するため、定期的（週1回など）に「取得して分析」を実行すると長期の推移が見られます。
- フォロー解除数（`follows_and_unfollows`）を取得できないアカウントでは、新規フォロー数（`follower_count`）でフォロワー推移を推定します。この場合、推移は実際より多めに表示されます（画面に注記が出ます）。
- フォロワー数が100人未満のアカウントでは、フォロワー関連のインサイトは取得できません。
- 長期間使えるトークンの有効期限は60日です。期限が切れたら再発行してください。

### 2. CSV 取り込み

Meta Business Suite の「インサイト → エクスポート」で出力した CSV を**そのまま**読み込めます。
ダウンロードしたファイルをまとめて選択（またはドロップ）してください。ファイルごとに中身を判別して1つのデータに統合します。

| ファイル（例） | 読み取る内容 |
|---|---|
| `Jun-26-2026_Sep-23-2026_….csv` | 投稿データ（投稿ID・公開日時・投稿タイプ・説明・ビュー・リーチ・いいね・シェア・フォロー・コメント・保存・アカウント名） |
| `Reach.csv` / `Views.csv` | 日次のリーチ・ビュー |
| `Visits.csv` / `Link clicks.csv` | 日次のプロフィールアクセス・リンククリック |
| `Interactions.csv` / `Follows.csv` | 日次のコンテンツインタラクション・フォロー |
| `Audience.csv` | フォロワー総数、年齢×性別、上位の都市、上位の国 |

自作の CSV も読み込めます。列名から次の2種類を自動で判別します。

| 種類 | 必要な列（例） |
|---|---|
| 投稿データ | 公開日時、いいね！、コメント、保存数、シェア、リーチ、投稿タイプ、説明 |
| 日次データ | 日付、フォロワー数 または 純増数（新規フォロワー／フォロー解除でも可）、リーチ |

**フォロワー以外へのリーチ（任意）**：投稿データ・日次データに「フォロワー以外へのリーチ」（`Non-follower reach`・`非フォロワーのリーチ` なども可）の列があれば読み込みます。「フォロワーへのリーチ」の列しか無い場合は「リーチ − フォロワーへのリーチ」で計算します。Meta Business Suite の標準の書き出し（投稿の CSV、`Reach.csv`）にはこの内訳が含まれないため、その場合は「平均リーチ／投稿」の下に「非フォロワー：データなし」と表示されます。Instagram API 連携では、アカウントの日次の値と（取得できる場合は）投稿ごとの値を自動で取得します。

**リーチ内訳の CSV（非フォロワー数の推定）**：期間ごとのリーチのフォロワー／非フォロワーの内訳を、次の形式でそのまま読み込めます（列の順番は自由）。

```
取得日,アカウント,期間,Instagramリーチ合計,From followers,From non-followers,非フォロワー比率
2026-10-02,miselclinic_osaka,2026-09-04～2026-10-01（直近28日）,38400,2656,36541,93.2%
```

非フォロワーの実数が無い投稿・日は、その日を含む期間（無ければいちばん近い期間）の **非フォロワー比率 × リーチ** で推定し、画面では「（推定）」や「≈」を付けて実数と区別します。比率の列が無い場合は From non-followers ÷（From followers ＋ From non-followers）で計算します（Meta は両方に届いた人を両方に数えるため、リーチ合計とは一致しません）。アカウント名が一致しない内訳は使いません。リーチ内訳の CSV だけを読み込んだときは、表示中のデータに追加されます。

英語の列名（`Publish time`, `Likes`, `Reach` など）にも対応しています。書式は [samples/](samples/) を参照してください。

**ソーシャルインサイト（Social Insight）の CSV**：書き出した UTF-8 の CSV を、そのまま（名前を変えずに）読み込めます。ファイル名からアカウント名と期間も読み取ります。

| ファイル（例） | 読み取る内容 |
|---|---|
| `si__accounts-posts_<アカウント>_instagram_<開始>-<終了>_utf8.csv` | 投稿一覧（投稿時間・詳細URL・タイプ・内容・画像URL・フォロワー数・いいね数・コメント数・動画再生回数・エンゲージメント率・いいね偏差値） |
| `si__accounts-summary_<アカウント>_instagram_<開始>-<終了>_utf8.csv` | アカウント日次（日時・投稿数・フォロー数・フォロワー数）。**日次のフォロワー数はこのファイルが最も正確**です |
| `si__accounts-hashtag_analysis_<アカウント>_<開始>-<終了>_utf8.csv` | ハッシュタグ分析（タグごとの投稿件数・いいね数・コメント数・エンゲージメント率の合計／平均／中央値） |
| `si__accounts-followed_<アカウント>_instagram_<取得日時>_utf8.csv` | フォロー中アカウント一覧（ユーザーネーム・プロフィール・よく使うハッシュタグ・フォロー数・フォロワー数・投稿数） |
| `si__instagram_insights-posts_<アカウント>_<開始>-<終了>_utf8.csv` | **投稿インサイト**（Instagram 連携版）。閲覧数・リーチ・いいね・コメント・保存・保存率・シェア・エンゲージメント・直フォロー・プロフィール遷移・再生時間・スキップ率。**投稿データはこのファイルが最も詳しい**です |
| `si__instagram_insights-summary_<アカウント>_<開始>-<終了>_utf8.csv` | **日次インサイト**。フォロワー数・増加数・減少数・閲覧数・リーチ（フォロワー／フォロワー以外・面別）・エンゲージメント・いいね・保存・シェア・プロフィールアクセス・各種クリック。**日次データはこのファイルが最も詳しい**です |
| `si__instagram_insights-stories_<アカウント>_<開始>-<終了>_utf8.csv` | ストーリーズのインサイト（閲覧数・閲覧率・リーチ・返信・直フォロー・プロフィール遷移・離脱・タップ・スワイプ・リンククリック） |
| `si__instagram_insights-tagged_<アカウント>_<開始>-<終了>_utf8.csv` | タグ付けされた投稿（他アカウントの投稿。ユーザーネーム・キャプション・いいね・コメント） |
| `si__instagram_insights-hashtag_<アカウント>_<開始>-<終了>_utf8.csv` | ハッシュタグ分析（インサイト版）。タグごとの閲覧数・リーチ数・いいね数・保存数・エンゲージメント率 |

取り込み時の扱い:

- **投稿時間は日本時間**として読みます（投稿インサイトは `2026-07-01 18:48:20 +0900` のようにタイムゾーン付きなのでそのまま、それ以外は日本時間として解釈）。Meta Business Suite の書き出しは米国太平洋時間なので、そちらとは解釈が異なります。
- 投稿は投稿URLの短縮コード（`si:DeMGEkcBqm5`）を ID にするため、期間が重なる書き出しを何度読み込んでも重複しません。**投稿一覧と投稿インサイトも同じ投稿としてまとまり**、足りない指標を補い合います（新しい方に値が無い項目は、前に取り込んだ値を残します）。ただし Meta の書き出し・API の投稿とは ID 体系が違うので、同じ投稿が二重に並びます。**投稿データはソーシャルインサイトか Meta のどちらか一方に寄せてください。**
- **投稿一覧（accounts-posts）にはリーチ・保存・シェアの列がありません**。この書き出しだけの場合、エンゲージメントは「いいね＋コメント」で計算され、エンゲージメント率の基準は「フォロワー」のみ使えます（「リーチ基準」は空になります）。投稿インサイト（instagram_insights-posts）を一緒に読み込めばリーチ基準も使えます。
- 書き出しが報告するエンゲージメント率は、分母が違うため別の項目として保持します（投稿一覧＝フォロワー基準 `erByFollowers`、投稿インサイト＝閲覧数基準 `erByViews`）。ハッシュタグ分析も同様で、アカウント版（フォロワー基準）とインサイト版（閲覧数基準）は**同じタグ・同じ期間でも別の行として残します**（`source` と `erBasis` で区別）。
- 投稿一覧の「フォロワー数」は**その投稿時点の値**なので、投稿に持たせたうえで日次のフォロワー数にも使います（同じ日に複数の投稿があれば、その日の最後の投稿の値）。投稿の無い日は空のまま（補間しません）。アカウント日次（`summary`）を一緒に読み込めば、投稿の無い日も埋まります。
- アカウント日次の「**フォロー数**」は**自社がフォローしている数**で、その日の新規フォロー数ではありません。Meta の書き出しの「フォロー数（＝新規フォロー数）」と混同しないよう、日次指標には入れず別に保持します。アカウント日次（`accounts-summary`）で日次データに入るのは**フォロワー数のみ**で、純増減はフォロワー数の前日差から計算します。「投稿数」も累計値なので同様に別扱いです。
- 日次インサイト（`instagram_insights-summary`）では、**フォロワー増加数＝新規フォロー／フォロワー減少数＝フォロー解除**として日次データに入れます。リーチ・閲覧数・エンゲージメント・プロフィールアクセス・ウェブサイトのクリック・エンゲージメントしたアカウント数もこのファイルから入り、**「フォロワー以外へのリーチ」も実数**で入るため、リーチ内訳 CSV による推定は不要になります（実数がある日は推定しません）。面（フィード／リール／ストーリーズ／広告）別の内訳・クリック種別・フォロワー転換率は、日次指標とは別に保持します。
- アカウント日次と日次インサイトを両方読み込んでも、同じ日は1行にまとまり、片方にしか無い項目（累計投稿数・面別の内訳など）は残ります。
- **ストーリーズは投稿（フィード・リール）と指標が違う**ため、投稿データには混ぜず別に保持します（エンゲージメント率や曜日・時間帯の分析はフィード投稿だけで行うため）。
- **タグ付けされた投稿は他アカウントの投稿**（例: 院長アカウント）なので、自社の投稿データには混ぜず別に保持します。
- ハッシュタグ分析は**集計期間ごとの値**なので、期間の違う書き出しは上書きせず両方残します（同じ期間の読み直しは上書き）。
- ハッシュタグ分析とフォロー中アカウント一覧だけを読み込んだときは、表示中のデータに追加されます。
- 「内容」「プロフィール」は引用符で囲まれないため本文の半角カンマで列がずれますが、増えた分はその列に戻して読みます。

### 3. GA4（HPへの流入）の取り込み

Instagram から着地先ホームページへの流入を、同じ画面で投稿データと突き合わせられます。**Excel（.xlsx）でも CSV でも**同じ場所から読み込めます。

「**日付・参照元/メディア・セッション**」の3列がある表を自動で探します。ほかに次の列があれば一緒に取り込みます。

| 列 | 使いみち |
|---|---|
| エンゲージのあったセッション / ユーザー / 新規ユーザー | 流入の質を見る。上部の「流入数（UU数）」「新規ユーザー数」「新規率」「エンゲージメント率」 |
| キャンペーン（utm_campaign）・コンテンツ（utm_content） | UTM キャンペーン別の流入 |
| 予約タップ・CV（コンバージョン・キーイベント） | 流入から先の通過率、上部の「予約完了数（CV数）」「CVR」 |

- Excel ブックは**全シート**を調べるので、シート名は自由です。説明行が上にあっても構いません。
- 「参照元別」と「キャンペーン別」の表が両方あるブックでは、同じ流入を二重に数えないよう、**粗いほう（参照元別）だけ**を合計に使います。キャンペーン別は UTM 別の表に使われます。
- 参照元/メディアに `instagram` / `ig` / `insta` を含む行だけを Instagram 流入とみなします。`/ paid` `/ cpc` は**広告**として分けて集計します。
- `web_instagram_okudate` のようにアカウント名が入った参照元は、Instagram アカウント別に振り分けます。
- GA4 が**週次**（週の初日が並んでいる）でも日次でも、どちらも週単位に揃えて突き合わせます。
- 画面上部の「Instagram からホームページへの流入」には、表示中の期間の Instagram 流入（広告込み）の合計を出します。アクセス数はセッション数、新規率は新規ユーザー ÷ ユーザー、エンゲージメント率はエンゲージのあったセッション ÷ セッション、CVR は CV ÷ セッションです。UU数はユーザー列の合計（日ごと・参照元ごとの合計なので、期間全体の重複なしユーザー数より多めに出ます）。
- 上部の各指標の「**推移をみる**」を押すと、別タブでその指標の過去の推移（グラフと表）が開きます。日別・週別・月別を切り替えられ、表は CSV で書き出せます。率の指標は分子・分母も表に並べます。

**相関について**

投稿側の指標（投稿数・リール本数・リーチ・反応数など）と、HP 側の指標（オーガニック流入・予約タップ）の相関を表にします。相関係数 r だけでなく次も並べています。

- **順位相関 ρ**：1週だけバズった、のような外れ値の影響を受けにくい見かた
- **p 値・95% 信頼区間**：その相関が偶然でも起きうる程度かどうか
- **時期の影響を除いた r（偏相関）・増減どうしの r（差分相関）**：両方が同じ時期に伸びただけの「見かけの相関」を見分けるための値。元の r より大きく下がる指標は、因果を疑ってかかる必要があります

週数が少ないうちは相関係数は大きく振れます。**10週以上**たまってから判断してください。相関は因果ではありません。

**取り込みの仕様**

- **文字コード**：UTF-16（Meta のエクスポート）・UTF-8・Shift_JIS を自動判別します。先頭の `sep=,` 行にも対応しています。
- **ファイル名**：`Reach.csv` のような1指標のファイルは、表題かファイル名で指標を判別します。**名前を変えずに**読み込んでください。
- **複数セクション**：`Audience.csv` のように1つのファイルに複数の表が入っていても、すべて読み取ります。
- **フォロワー数の推移**：Meta のエクスポートにはフォロワー総数の日次推移が含まれません。`Audience.csv` の現在のフォロワー数を起点に、`Follows.csv` の日々のフォロー数をさかのぼって推移を推定します。フォロー解除数が含まれないため、**過去の値は実際よりやや少なめ**に出ます（画面に注記が出ます）。
- **複数アカウント**：1つの投稿エクスポートに複数アカウントが含まれる場合、画面上部の「アカウント」で絞り込めます。日次の指標（リーチ・プロフィールアクセスなど）はアカウント合計のため、絞り込みの対象外です。
- **追加取り込み**：「現在のデータに追加」にチェックを入れたまま別の期間のファイルを読み込むと、日付単位でマージされて期間が伸びます。読めないファイルが混ざっていても、読めたファイルは取り込みます。

### 4. デモデータ

架空アカウントの180日分のデータです。

## 指標の定義

- **エンゲージメント率（ER）**
  - リーチ基準（初期設定）：（いいね＋コメント＋保存＋シェア）÷ リーチ × 100
  - フォロワー基準：（いいね＋コメント＋保存＋シェア）÷ 投稿時点のフォロワー数 × 100
- **最適な投稿時間帯**：投稿した曜日と3時間ごとの時間帯で平均 ER を集計しています。投稿数が少ない枠の偶然の高い値に引っ張られないよう、全体平均に寄せて補正した値（ベイズ平均）で順位を付け、おすすめ枠は2投稿以上ある枠だけから選んでいます。曜日・時間帯は日本時間（UTC+9）で判定します。投稿日時は UTC（末尾 Z）で保存されているため、例えば `2026-09-30T09:02:09.000Z` は「2026年9月30日（水）18:02:09（日本時間）」として扱います。Meta Business Suite の書き出し（Publish time: `07/16/2026 02:00` の形式）は米国太平洋時間で書かれているため、夏時間も考慮して日本時間に直して読み込みます（例: `09/30/2026 02:02` → 9月30日（水）18:02）。それ以外のタイムゾーン表記のない日時（`2026/09/30 18:02` など）は日本時間として読み込みます。

## データの保存先とセキュリティ

- データはブラウザの localStorage にのみ保存されます。サーバー側には何も保存しません。
- アクセストークンは「トークンをこのブラウザに保存する」にチェックを入れた場合だけ保存されます。共有 PC ではチェックを外してください。
- トークンは Instagram Graph API（graph.instagram.com / graph.facebook.com）への通信にだけ使います。
- 「デモ・管理」タブから JSON でバックアップと復元ができ、保存データとトークンの削除もできます。
